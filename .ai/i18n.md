# Internationalisation

Last reviewed: 2026-10-23

Two locales: `en` (the source of truth) and `pl`. There is one i18next namespace, `translation`.

## Content

- Every locale contains every key. Change `en` and `pl` in the same commit. Project decision.
- A string that interpolates a count passes `count`, and every language that needs plural forms declares them: `en` declares the base key (plus `_one` where English differs), and `pl` adds `_one`, `_few` and `_many`. Why: i18next has no fallback to the base key when `count` is missing, so Polish would render one fixed case. Source: https://www.i18next.com/translation-function/plurals
- Language-invariant facts stay in `src/data/`; translatable prose stays in `src/locales/<lng>.ts`. See `.ai/architecture.md`. Project decision.

## Typed keys

- Translation keys are derived from the shape of `en` (`src/i18n/keys.ts`, `src/i18n/types.ts`). Read strings with `t()` and bullet lists with `tList()` from `@i18n/useTranslation`. Enforced by: the TypeScript compiler.

## Adding a locale

- Register a new locale in `src/i18n/config.ts` and `src/i18n/resources.ts`. The steps are in `README.md`, section "Adding a language". Project decision.
